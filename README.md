# Enterprise Admin — Go + React Admin Scaffold

> **Language:** English (default) · [中文文档](./README.zh-CN.md)

A full-stack admin scaffold inspired by `go-admin` / `go-admin-ui`, built around a
dual-track design of **Actions mode (zero-code CRUD)** and **Regular mode
(hand-written logic)**:

- Simple CRUD → declare one resource and get list/detail/create/update/delete
  plus type-safe filtering with **zero code**.
- Complex business logic → hand-write handlers/controllers with a **type-safe
  query builder**.

## Stack

| Layer    | Tech |
|----------|------|
| Backend  | Go 1.23 · Gin · GORM (SQLite by default, MySQL/Postgres supported) · Swagger (swag) · JWT |
| Frontend | React 18 · refine (@refinedev/core + antd) · Ant Design 5 · Vite 8 · TypeScript |
| Features | Unified envelope `{code,data,msg}` · type-safe queries · tabbed keep-alive views · lightweight RBAC · operation logs |

## Minimal Docker Deploy (sqlite, no nginx)

The Go binary serves **both** the API and the frontend production build on a
single port — no nginx, no separate static server, no external database:

```bash
docker compose up -d --build
# open http://localhost:8080 (admin / admin123)
```

Or with plain docker:

```bash
docker build -t enterprise-admin .
docker run -p 8080:8080 -v ea-data:/app/data enterprise-admin
```

The sqlite file persists in the `ea-data` volume (`/app/data`), uploads in
`./uploads`. Environment overrides:

| Env var       | Default                      | Purpose                    |
|---------------|------------------------------|----------------------------|
| `PORT`        | `8080` (config `server.port`) | listen port               |
| `WEB_DIR`     | `./web`                      | frontend `dist` directory  |
| `SQLITE_PATH` | config `sqlite.path`         | sqlite file location       |
| `CONFIG_PATH` | `config/settings.yml`        | config file location       |

## Commands (root Makefile)

```bash
make help          # list all commands
make gen           # regenerate the gorm type-safe query package (re-run after changing models/)
make build         # compile the backend binary to backend/bin/enterprise-admin
make run           # run the backend locally (sqlite :8080 by default)
make tidy          # tidy Go dependencies
make dev-backend   # start the backend dev server (:8080)
make dev-frontend  # start the frontend dev server (:5173, proxies /api to :8080)
make dev           # start both backend and frontend dev servers
make docker-build  # build the minimal image (sqlite, Go serves the frontend)
make docker-up     # one-command minimal deploy (sqlite persisted in a volume, :8080)
```

Run a built binary (from `backend/`, config/DB paths are relative):

```bash
cd backend && ./bin/enterprise-admin   # listens on :8080, auto-migrates + seeds
```

## Run

### Backend
```bash
cd backend
go mod tidy
go run ./cmd/gen         # generate the gorm/gen type-safe query package (genquery/); re-run after model changes (same as make gen)
go run .                 # sqlite by default, listens on :8080, auto-migrates + seeds
# Swagger: http://localhost:8080/swagger/index.html
```
Default account: `admin / admin123`

Switch database (`config/settings.yml`): `driver: mysql|postgres`, plus the
matching DSN. In containers prefer `SQLITE_PATH` for the sqlite location.

Regenerate the swagger docs:
```bash
swag init -g main.go -o docs
```

### Frontend
```bash
cd frontend
pnpm install
pnpm dev                 # http://localhost:5173 (proxies /api -> :8080)
```
Proxies configured: `/api`, `/login`, `/uploads`, `/swagger`.

The frontend talks to the backend through a typescript-axios client generated
from swagger (`src/api/`, do not edit by hand), wrapped in
`src/api/client.ts` (axios instance + JWT + `{code,data,msg}` unwrapping):
```bash
pnpm gen:api             # after backend API changes: swag init → regen → typecheck
pnpm typecheck
```
URLs stay relative, so the same build works both behind the Vite dev proxy and
behind the Go static server in the docker image.

## Dual-Track In Practice

### 1. Actions mode (zero code)
The backend only declares a resource:
```go
actions.NewResource[models.Product](db).
    WithName("demo/product").
    WithHooks(actions.Hooks[models.Product]{
        BeforeCreate: func(c *gin.Context, m *models.Product) error {
            m.SetCreateBy(auth.GetUserID(c)); return nil
        },
    }).
    Register(v1)   // GET/POST /demo/product, GET/PUT/DELETE /demo/product/:id for free
```
The frontend only adds one `ResourceMeta` in `resources/meta.ts` plus a
registration in `registry.tsx`, and gets list/search/create/edit forms with
**no page component written**.

Type-safe HTTP filtering (field names/types validated at the schema layer,
illegal fields get a 400):
```
GET /api/v1/demo/product?name__like=keyboard&price__gte=1000&stock__lte=30&sort=-price
```

### 2. Regular mode (hand-written complex logic)
`controllers/order.go` uses **gorm's own type-safe queries** (the `genquery`
package generated by `gorm/gen`); field accessors are compile-time type-safe,
so a misspelled field or wrong value type fails compilation:
```go
var conds []gen.Condition
if minAmount > 0 {
    conds = append(conds, genquery.Order.Amount.Gte(minAmount))   // float64 field
}
if len(statuses) > 0 {
    conds = append(conds, genquery.Order.Status.In(statuses...))  // string field
}
list, _ := genquery.Order.Where(conds...).
    Order(genquery.Order.ID.Desc()).
    Offset((page-1)*size).Limit(size).Find()
total, _ := genquery.Order.Where(conds...).Count()
```
New models join type-safe querying by regenerating: `go run ./cmd/gen`
(generates `genquery` from the `models` package).
Hand-written routes (arbitrary aggregation/validation beyond Actions mode):
```go
v1.GET("/order", order.List)              // list + revenue summary (gen type-safe filters)
v1.GET("/order/stats", order.Stats)       // group by status
v1.PUT("/order/:id/paid", order.MarkPaid) // business action
```

### Type-safe query notes
- **Hand-written logic uses `gorm/gen`** (`genquery.Order.Amount.Gte(...)`):
  gorm's own code generator emitting query methods with field type info, so
  conditions are checked at compile time.
- Actions mode's `core/query.ParseFilters[T]` validates HTTP filter params'
  field names and value types at the API boundary.

## API Contract
Unified response: `{ "code": 200, "data": ..., "msg": "ok" }`. `code != 200`
means an error.
- Paginated list: `data = { list, total, page, pageSize }`
- Detail/create/update: `data = the record`
- Delete: `data = null`

## Extend
- **New zero-code resource**: define `models.Xxx`, call
  `actions.NewResource[models.Xxx](db).WithName("demo/xxx").Register(v1)` in
  `router.go`, add `ResourceMeta` + registration on the frontend.
- **New hand-written resource**: write handlers in `controllers/`, register in
  `router.go`, add a page component on the frontend.
- **Permissions**: the `RequireRoles(...)` middleware in `core/auth/rbac.go`
  can be mounted on any route (the admin role passes by default).
